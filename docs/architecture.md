# Architecture

## Local index

The local index is a file-backed, synchronous SQLite module exported from `src/index-store/`. Its `IndexedPage` input separates provider acquisition and normalization from persistence, while its read APIs separate local retrieval from model-facing presentation. The store persists records and exposes local search, page metadata, pruning, and bounded reads. It does not make network requests, decide Notion scope, validate page UUIDs, or sanitize provider content.

### Data and transactions

`state` stores text key/value metadata for later credential binding, scope, and synchronization cursors. `pages` stores the opaque page ID, title, URL, provider edit time, Markdown, incompleteness flag, content hash, and indexing time. `pages_fts` stores the source title and Markdown plus separate title and Markdown projections for ordinary words and CJK bigrams; its page ID column is unindexed. The FTS table's fixed shadow tables are part of the owned schema.

Every insert or content-bearing update writes `pages` and `pages_fts` in one immediate transaction. Updates delete the prior FTS row before inserting its replacement. Page deletion and full-catalog pruning remove both representations in the same transaction. An unchanged upsert preserves the prior `indexed_at` value. An empty pruning keep-set deliberately deletes every indexed page.

### Format ownership and permissions

The database format uses `application_id` `0x4453484e`, the four-byte ASCII value `DSHN`, and `user_version` `1`. Before a writable open, classification reads the fixed SQLite header and queries the file through a read-only connection. A normal current-schema open checks ownership, version, the complete schema, and its object allowlist without scanning every database page. If an owned header is accompanied by a hot rollback journal and SQLite reports `SQLITE_READONLY_ROLLBACK`, classification copies the main file and ordinary-file sidecars into a same-parent private temporary directory, lets SQLite recover that copy, and runs a full integrity check before accepting its application ID, version, and schema. A failed recovery leaves the original main file, sidecars, and permissions unchanged. Sidecar symbolic links and other non-regular files are never followed. A nonzero foreign application ID, an application ID of zero with any schema, and a file that cannot establish SQLite or plugin ownership fail without chmod or replacement.

The store rejects symbolic links and junctions in the index parent path. On POSIX systems, each path entry must be protected from rename by a containing directory owned by root or the current user. A group- or world-writable containing directory must additionally have the sticky bit and contain a child owned by the current user. These checks run before a missing child is created. New parent directories use `0700`, a pre-existing final parent must belong to the current user and must not be group- or world-writable, and database files use `0600`; an owner-controlled `0755` final parent remains valid and is not changed. The main database must be a regular file with one hard link. Classification records its device and inode and snapshots the exact `-journal`, `-wal`, and `-shm` path identities. Before a current index is opened writable, the store rechecks the parent, database, and complete sidecar set; every present sidecar must remain the same regular file with one hard link. Before replacement, the same snapshot prevents a sidecar appearance, disappearance, or identity swap, while exact unlink cleanup still handles a stable dangling sidecar without following it. Every writable connection verifies `foreign_keys=ON`, `journal_mode=DELETE`, and `synchronous=FULL` together with the ownership identifiers and required schema. Schema validation checks the owned table definitions, including column types and constraints, strict and rowid-free tables, the content flag check, the unindexed FTS page ID, the `unicode61` tokenizer, the fixed FTS5 shadow tables, and the absence of unknown tables, indexes, views, or triggers. A bounded read-only row ID probe also verifies that FTS5 can construct the virtual table from those shadow objects.

Windows does not use POSIX mode bits as a confidentiality guarantee. The index relies on the current user's DSH home ACL and host disk encryption such as BitLocker; v1 does not create or manage Windows ACLs.

### Rebuild policy

The database is a derived index rather than the source of Notion content. An owned database with another schema version or an incompatible version 1 schema is replaced instead of migrated. A candidate with a different version or incompatible schema metadata receives a full integrity check before replacement is authorized. When the application ID and main FTS definition are exact but the bounded operational probe cannot construct the FTS virtual table, that failed probe directly classifies the derived index for rebuilding; a full scan is not attempted because the broken virtual table prevents it. Initialization then builds a complete database in a random same-parent private temporary directory, closes it, and reopens it read-only for ownership, schema, and full integrity validation. Only then does the store recheck path identities, remove the confirmed owned index's exact `-journal`, `-wal`, and `-shm` paths, and atomically rename the replacement over the final path. Cleanup uses path metadata rather than following symbolic links, so it also removes dangling sidecar links. A build, validation, identity, sidecar, or rename failure leaves the old main database in place. No glob or recursive deletion participates in rebuilding.

### Search and CJK tokens

FTS5 uses `unicode61`, but search binds only projections produced by the store's tokenizer so adjacent text such as `版本2`, `中文ABC`, and `企业Knowledge图谱` has the same token boundaries during indexing and querying. A pure tokenizer recognizes Han, Hiragana, Katakana, and Hangul through Unicode Script Extensions, retains text continuations such as the Japanese prolonged sound mark, and emits overlapping two-code-point tokens within each contiguous run. A single-code-point run produces no synthetic token, and punctuation or ordinary text ends a run. Ordinary and CJK title and Markdown tokens are stored in separate columns so BM25 can apply a `5:1` title-to-body weight. Internal projections are not returned through page APIs.

Search never forwards the input query as FTS syntax. It extracts lowercase Latin and numeric words after excluding CJK code points, generates CJK bigrams separately, quotes the resulting tokens, scopes each group to its two projection columns, and binds the complete expression as a `MATCH` parameter. Tokens within each group use AND, and mixed queries require both groups. Page ID provides deterministic ordering for equal scores. Snippets are computed from the stored Markdown around the earliest token and are bounded by Unicode code points.

### Bounded reads

Page reads split CRLF, CR, and LF into logical lines and return LF-joined windows. Both the line and Unicode code-point budgets are enforced. One trailing line terminator does not create a phantom line. If a logical line alone exceeds the character budget, the store returns its bounded prefix, marks `lineTruncated`, and advances `nextStartLine` to the next real line instead of repeating the truncated line. Content sanitization remains the responsibility of the synchronization layer.

## Notion synchronization

The `src/notion/` module owns provider acquisition, scope binding, Markdown sanitization, and the SDK transport. `syncNotionWorkspace` is transport-agnostic and is backed by the official `@notionhq/client` transport in `src/notion/transport.ts`. Synchronization is read-only: it uses `users.me`, paginated search for pages and data sources, parent metadata, and the Markdown retrieval endpoint. It never creates, updates, or deletes Notion content.

Before the first provider request, the sync engine verifies identity so a failed credential check cannot clear the previous binding. Then `beginIndexBinding` compares a salted HMAC of the resolved token and an order-independent root-page fingerprint. A changed token or root scope deletes all previously indexed pages and the active freshness state before the new catalog is fetched. `activateIndexBinding` persists the new binding only after the catalog is complete and every required page was fetched. A provider failure leaves the previous pages in place and does not advance `last_success_at`.

Catalog enumeration is bounded by `maxCatalogItems`; an incomplete `request_status` or an over-limit catalog fails with `catalog-incomplete`. Each configured root must be present and available, otherwise the run fails before pruning. Only new or changed pages call the Markdown endpoint. Markdown sanitization removes dangerous control characters and presigned media URLs, caps the body by Unicode code points without splitting surrogate pairs, and records provider truncation and unknown block IDs as `content_incomplete`.

## Binding and read surfaces

`assertActiveIndexBinding` is the gate for `notion_search` and `notion_read`. It resolves the credential on every operation, recomputes the token HMAC and root fingerprint, and returns actionable `token-changed`, `scope-changed`, `index-missing`, `not-configured`, or `credential-missing` errors. Tools query only the local index; they never perform a live Notion request. Search validates that a query has at least two non-whitespace Unicode characters. Read windows come from the local line-oriented store API and carry pagination metadata.

The bundle prompt states that Notion content is data, not instructions, and asks the model to cite the returned page URL. Search and read results are ordinary model-visible content and therefore enter the standard DSH session log.

## Commands and lifecycle

`/notion-sync` and `/notion-status` are registered even while `rootPages` is empty. Model tools and the prompt section are registered only after roots are configured. The command runtime allows one manual sync at a time; a concurrent run returns `sync-in-progress`. `/notion-status` projects workspace, root count, indexed page count, freshness timestamps, and run state without printing the absolute index path or the token. On startup, an existing successful index that is older than `staleAfterMinutes` schedules a non-blocking background refresh. Plugin teardown disposes tool, prompt, and command registrations and closes the SQLite connection; it does not delete the index file.
